# 星落蓝图 · 基础工业原型

基于 `../RE_BFL` 的公共科技设定，面向 **Minecraft 1.21.1 / NeoForge 21.1.262 / Java 21**。版本 `0.1.0` 实现第一段公共整备闭环；不是设定中全部23条产线的完成版。

## 已实现内容

- 主世界陨相矿与深层宿主变体，铁镐及以上采收；不额外生成五种功能矿。时运同时增加原矿份数和较高品位的概率，普通/深层规则相同；精准采集不掉可放置矿块。具体规则及本轮验证结果见下文。
- 服务端物料组件：材质、干量、陨相组分量、完整度、污染、形态和路线。每份晶料10M，原矿1000M。不同品质保留独立堆叠。
- 整备台 PC-R01：200刻（20TPS时10秒），每批250mB水、40,000XH，煤/木炭320,000XH。G6/12/24分别产5/10/20份P90%通用晶料；完整度扣2；尾砂保留全部剩余干量和陨相组分。
- CB-01省能接头：每批36,000XH，单件有效，180XH/刻扣除，保留余能。升级变动只影响下一批，不追溯修改在制批次。
- CB-02工具加固扣、CB-03盾面衬片：通过工作台安装，最大耐久+20%，按向上取整的损伤比例保留损耗，不增加采掘等级，不可重复安装。
- CB-04近距寻矿指示片：右键扫描8格球形范围、40刻冷却；只报告有无信号，不暴露坐标或品质，不加载区块。
- 整备台中文/英文界面、实时进度、停机原因、水量、余能、自动亮起与四向摆放；中文营地手册和三项入门进度。
- 漏斗自动化：顶面投矿，侧面投煤，底面取成品与尾砂；NeoForge普通水输入接口。原版漏斗本身不能输水，可手动用桶补水。
- 加工前同时验证水、能源与两种出料空间；批次预留输入，欠能/堵塞暂停；保存、卸载、拆移后续作，不补算离线产量。
- 机器拆除打包真实库存、水、余能、接头及在制批次到唯一机器物品，不另掉一份内部库存。
- 常压储水罐与营地集雨器：4000mB空罐出厂；真实露天降雨收集100mB/秒，底面直接朝下供水；可把集雨器放在整备台或常压罐上方。晴天不产水，已存水仍可流出。桶装取水与拆移保持库存；已有水的罐升级集雨器时继承实际水量。
- 原创16×16像素方块/物品贴图、深色工业界面及可重复生成的源脚本。

## 生存起步

1. 用纸+圆石无序合成营地工务手册，右键阅读。
2. 在新生成的主世界区块、Y=-64至32寻找陨相矿，用铁镐或更高工具采收。也可用创造页的三种品位原矿检查工艺。
3. 在工作台制造整备台：

   ```text
   铁 铁 铁
   石 铜 石
   石 空 石
   ```

   石为圆石，合计3铁、1铜、4圆石，不需要晶料或控制板。

4. 水桶右键整备台加水，一桶1000mB支持4批。空手或普通物品右键打开界面，左上放原矿，左下放煤/木炭。每批10秒。潜行持空桶右键可取回整桶剩水。
5. 晶料+铜锭无序合成省能接头，右键整备台安装，也可放入界面右下附件位。界面本批预算可能仍为40kXH：新接头从下一批起生效。
6. 继续制造基础成品：

   | 成品 | 配方 | 使用 |
   | --- | --- | --- |
   | 工具加固扣 | 晶料在上、铁锭在下，竖直两格 | 加固扣+普通镐无序合成 |
   | 盾面衬片 | 晶料在左、铁锭在右，水平两格 | 衬片+原版盾牌无序合成 |
   | 寻矿指示片 | 晶料+铜锭+红石，无序 | 手持右键 |

   晶料配方在服务端检查Q0品质，低I/污染/错误形态或路线不能仅靠物品ID混入。加固扣与衬片物料相同，以横/竖摆法区分。

加固装备修理与升级：工作台或砂轮合并同类装备，保留任一输入的加固，最大耐久取两者较大值，不重复叠加；工作台按原版清除名称和普通附魔、保留诅咒，砂轮沿用上槽名称和组件。铁砧以左侧为目标，想保留加固时应把加固装备放左侧；右侧只作为修理/附魔材料消耗，不转移加固。加固钻石镐使用原版模板和下界合金锭升级后，上限为2437，按比例向上取整保留已损耐久，并保留名称和附魔。

水4000mB、普通尾砂槽最多16批同种尾砂。晶料库存满、尾砂库存满或品质不兼容会停机；取走产物后自动恢复。

储水罐：4玻璃围住1铁锭的十字摆法。集雨器九宫格如下（罐为常压储水罐，木为任意木板）：

```text
铁 玻 铁
玻 罐 空
木 木 木
```

集雨器必须露天且处于真正下雨的生物群系；放在整备台正上方即可自动补水。普通储水罐本身不主动泵水。空手右键罐/集雨器查看水量，水桶右键加入，空桶右键取出整桶水。

## 构建和运行

安装JDK21。首次构建需要联网下载Gradle、Minecraft与NeoForge依赖，不依赖其他模组。

```powershell
.\gradlew.bat build
.\gradlew.bat runGameTestServer
.\gradlew.bat runClient
.\gradlew.bat runServer
```

Linux/macOS使用 `sh gradlew ...`。JAR输出到 `build/libs/starfall_blueprint-0.1.0.jar`，安装到双方Minecraft实例的`mods`目录。首次启动独立服务器后需由服主确认Minecraft EULA。本项目不自动接受条款。

资源已提交，正常构建不需要Python。重建美术和数据资源可运行：

```powershell
python -m pip install Pillow
python tools/generate_resources.py
python tools/verify_resources.py
```

## 验证与设计边界

2026-10-20完整构建成功，真实NeoForge服务端**23项GameTest全部通过**：覆盖燃料8批预算、低品位物料守恒、接头10%节能及中途变更、缺水/堵塞/欠能续作、保存恢复、品质合成校验、镐/盾耐久升级和流体接口模拟；另包含生存桶主副手交互、真实储水罐拆放、原版漏斗连续两批生产，以及铁砧材料修理和砂轮单件去附魔。已修复整备台潜行空桶抽水被原版交互链跳过的问题。 逐模块状态见 [开发进度](docs/PROGRESS.md)，验证结果与技术说明见 [实现说明](docs/IMPLEMENTATION.md)。

当前自然生成采用稀疏矿脉原型（每4区块一次尝试、矿脉大小4、Y=-64至32），**尚未实现撞击带分布，也没有完成设定要求的20种子密度校准**。矿块自然密度不因时运改变，采收产出预算须计入时运的份数和品位收益。品位暂收敛为G6/12/24，以避免首版分包取整。普通采收I30—40，时运不提高完整度、加工纯度或路线；本版没有高I采收与专业精制，后续低冲击工具设计保留。

本轮时运规则（已通过服务端回归）：等级截断为L=0..3，无时运固定1份且不额外抽取数量随机数；L>0时份数为`max(1, random.nextInt(L + 2))`，时运I/II/III最多2/3/4份，也可能仍为1份。G6/G12/G24概率如下：

| 所用时运等级 | G6 | G12 | G24 |
| --- | --- | --- | --- |
| 无时运 | 65% | 30% | 5% |
| I | 55% | 35% | 10% |
| II | 45% | 40% | 15% |
| III | 35% | 45% | 20% |

品质和份数由世界种子、矿坐标及所用时运等级确定，同条件重复计算稳定，无时运保持原输出。普通/深层宿主同规则，精准采集不掉可放置矿块，不能靠重放矿块重抽。每份原矿仍为1000M，整备台按份加工并保持干量和陨相组分守恒。上面的23项通过记录属于此前交互回归；本轮新增3项采收测试，完整构建与真实NeoForge服务端**26/26全部通过**，覆盖时运增产提品、无时运兼容、普通/深层一致、确定性、工具与精准采集边界及超III等级截断。见[本轮时运测试证据](docs/verification/2026-10-20-fortune-gametest.txt)。

当前公共首段直接开放，不伪造阵营研究系统。CB-05限额研究交易、NPC、三辅矿、月络/魔法、精制机、分化工序、机组/电网、自动合成台、并列熔炉及输送管网属于后续阶段；本版未注册占位空壳。流体接口供后续管路接入，不代表已完成取水泵或管网。实际游玩节奏、客户端画面和多人压力需继续验收，不能仅以编译或单服测试代替。
